## 2. Logic Chain

1. **Premise 1 (Sobel Edge Ratio Defect)**:
   `detect_stroke_is_sideways` computes the ratio of near-horizontal gradients (`< 30°`) to near-vertical gradients (`> 60°`). On lined paper, spiral notebooks (such as EV-35D17C96), and cursive handwriting, horizontal lines and horizontal writing strokes dominate, generating strong vertical gradients (`sobely >> sobelx`). This forces the ratio well below the 0.90 threshold (e.g. EV-35D17C96 ratio = 0.266).
2. **Premise 2 (Old Pipeline Coupling & False Sideways Rotation)**:
   In commit `0be82cd`, `is_sideways` determined candidate search (`cand1, cand2 = (90, 270) if is_sideways else (0, 180)`). When `is_sideways` fired falsely, 0° was never evaluated, forcing the OCR service to rotate the image 90° or 270°. `result["oriented_image_base64"]` was assigned `image_to_base64_data_uri(best_img)`, exporting the rotated image to the frontend.
3. **Premise 3 (Frontend Override Defect)**:
   In `DashboardPage.jsx:284`, `src={report.oriented_image_base64 || previewImage}` was used. Because `oriented_image_base64` was non-empty, it overrode `previewImage`, causing the user's submitted document to appear sideways.
4. **Premise 4 (Verbatim Preservation Failure in Current Code)**:
   The current working tree in `ocr.py` sets `result["oriented_image_base64"] = image_to_base64_data_uri(raw_img)`. `image_to_base64_data_uri` applies `convert("RGB")` and `save(..., format="JPEG", quality=85)`. This alters the byte stream (827 bytes -> 360 bytes), recompresses user images, strips PNG alpha channels, and fails the requirement to preserve raw uploaded bytes verbatim.
5. **Deduction (Solution Design)**:
   - To strictly satisfy R1, `oriented_image_base64` must be generated directly from raw input `image_bytes` (via a helper such as `raw_bytes_to_base64_data_uri(image_bytes, filename)`), ensuring `base64.b64decode(b64_data) == image_bytes` bit-for-bit.
   - Internal OCR candidate evaluation and deskewing for transcription must operate strictly on internal copies of the image (`raw_img`) without ever mutating `oriented_image_base64`.
   - In `test_orientation_adversarial.py:312`, the test previously asserted `result["oriented_image_base64"].startswith("data:image/jpeg;base64,")` even for PNG inputs. With verbatim preservation, a PNG upload yields `data:image/png;base64,`. The test must be updated to accept `data:image/png;base64,`.

## 3. Caveats

1. **Real-time GPU Model Inference**:
   Running live Qwen2-VL inference on large images requires significant GPU memory and takes ~3-8 seconds per image. Unit tests use mocked inference (`unittest.mock.patch`) to execute in under 6 seconds while rigorously verifying orientation logic and pixel invariance.
2. **Missing EXIF in Web Datasets**:
   Virtually all images in `evaluation/images` have stripped EXIF metadata due to web/WhatsApp compression. EXIF normalization must therefore be tested primarily via programmatic EXIF-tagged test fixtures (as implemented in `test_orientation_adversarial.py`).
3. **MIME Type Sniffing**:
   If an uploaded file has no filename or extension, MIME type detection should fall back to standard file magic byte headers (`\xff\xd8\xff` for JPEG, `\x89PNG` for PNG, `RIFF...WEBP` for WebP).

## 4. Conclusion & Proposed Test Specifications

### 4.1 Root Cause Summary
- **Primary Cause of Sideways Rotation**: False-positive triggers in `detect_stroke_is_sideways` caused by notebook ruling lines and horizontal strokes (ratio 0.266 < 0.90), coupled with candidate selection in `ocr.py` that forced evaluation of [90, 270] and overwrote `oriented_image_base64` with the rotated candidate.
- **Primary Cause of Byte Mutation**: Using `image_to_base64_data_uri(raw_img)` which re-encodes images through PIL at 85% JPEG quality rather than base64-encoding the raw uploaded file bytes.

### 4.2 Proposed Verbatim Encoding Implementation
Communication of proposed helper in `Deepfake/eduverify-ai/backend/api/services/orientation.py`:
```python
def raw_bytes_to_base64_data_uri(image_bytes: bytes, filename: Optional[str] = None) -> str:
    """Encodes raw uploaded image bytes verbatim into a base64 Data URI."""
    import base64
    if image_bytes.startswith(b"\x89PNG\r\n\x1a\n"):
        mime = "image/png"
    elif image_bytes.startswith(b"\xff\xd8\xff"):
        mime = "image/jpeg"
    elif image_bytes.startswith(b"RIFF") and len(image_bytes) >= 12 and image_bytes[8:12] == b"WEBP":
        mime = "image/webp"
    elif image_bytes.startswith(b"GIF87a") or image_bytes.startswith(b"GIF89a"):
        mime = "image/gif"
    elif image_bytes.startswith(b"BM"):
        mime = "image/bmp"
    elif filename:
        ext = filename.lower().split(".")[-1]
        mime_map = {"png": "image/png", "jpg": "image/jpeg", "jpeg": "image/jpeg", "webp": "image/webp", "bmp": "image/bmp"}
        mime = mime_map.get(ext, "image/jpeg")
    else:
        mime = "image/jpeg"
    b64_str = base64.b64encode(image_bytes).decode("utf-8")
    return f"data:{mime};base64,{b64_str}"
```
