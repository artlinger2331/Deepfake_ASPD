## 13. Top Failure Cases

Based on system architecture auditing and code inspection, the following critical failure modes exist:

1. **Failure Case 1: Pure Laplacian Variance Insufficiency**
   * *Problem*: High-resolution AI-generated handwriting images produced by modern diffusion models (e.g., Flux or SDXL) can exhibit sharp artificial edges ($\sigma^2_{\text{Laplacian}} > 100$), causing the visual module to score them as $0.12$ (genuine).
2. **Failure Case 2: Printed-Text Classification Void**
   * *Problem*: If a student submits a photographed textbook page or a printed essay, the system extracts the text with high confidence ($95\%$) and falsely labels it as `"Likely Genuine Handwritten Work"`.
3. **Failure Case 3: WhatsApp / Web Compression Metadata Stripping**
   * *Problem*: Authentic student homework submitted via WhatsApp has all camera sensor metadata permanently stripped by the compression algorithm, causing the metadata module to fall back to a `"warning"` status.
4. **Failure Case 4: C2PA Inactivity**
   * *Problem*: C2PA verification is entirely stubbed out in `metadata.py` and returns `False` on all files regardless of whether real cryptographic provenance manifests exist.

## 14. Recommendations for Improvement

1. **Implement Frequency-Domain Deepfake Detection**:
   * Replace the single-variable Laplacian filter with a 2D Discrete Cosine Transform (DCT) frequency anomaly detector or a fine-tuned ResNet/ViT feature extractor to detect diffusion noise fingerprints.
2. **Add a Dedicated Handwriting vs. Typeset Classifier**:
   * Integrate an initial classifier (e.g., lightweight MobileNet or stroke texture analysis) before the OCR stage to distinguish printed typography from human handwriting.
3. **Implement Two-Pass OCR Self-Correction**:
   * Implement a secondary verification pass where Qwen2-VL cross-checks its initial draft transcription against stroke line contours to restore skipped lines and eliminate hallucinated words.
4. **Wire Real C2PA Validation**:
   * Replace the hardcoded `c2pa_credentials: False` flag with the official `c2pa-python` library to read actual Content Credentials manifests embedded in modern mobile and camera images.
5. **Populate the Benchmark Suite**:
   * Place consented, de-identified sample images into the 8 subdirectories of `evaluation/images/` and run `python run_evaluation.py && python calculate_metrics.py` to produce live empirical metrics.

## 15. Limitations

1. **Sample Size**: The current evaluation suite is in the bootstrap phase with 0 active test executions recorded.
2. **Hardware Dependence**: Multimodal OCR inference speed depends heavily on local NVIDIA GPU VRAM availability (minimum 4 GB VRAM required for PyTorch FP16).
3. **Language Scope**: Current stroke-alignment and reading-flow algorithms are tailored to Latin/English script (top-to-bottom, left-to-right with dominant vertical downstrokes). Right-to-left scripts (e.g., Arabic, Hebrew) or vertical scripts (e.g., East Asian) are not currently supported.
4. **Scanner vs. Camera Bias**: Scanned documents lack camera sensor grain and natural lighting variations, which may cause variance-based heuristics to assign lower authenticity scores.
